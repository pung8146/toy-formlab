## 1. 목표와 성공 장면

위시캣과 포트폴리오 Work 섹션에 올릴 인터랙티브 3D 제품 configurator 토이 프로젝트다. 방문자가 램프를 돌려 보고, 부품의 형태·색·재질을 바꾸고, 불을 켜 보고, 같은 구성을 여는 링크를 보낸다.

대상과 우선순위는 다음과 같다.

| 보는 사람 | 보는 것 | 설계 반영 |
|---|---|---|
| 위시캣 의뢰인 | 썸네일, 짧은 영상, 몇 초의 조작 | 첫 화면 대비, 프리셋 칩, 점등 장면, 캡처 자산 |
| 포트폴리오 방문자 | 라이브 페이지 | 즉시 조작, 모바일에서 바로 회전 |
| 채용·개발 검토자 | README, 케이스 스터디 | 설계 결정과 알려진 한계의 정직한 기록 |

성공 장면은 다음과 같다.

- 링크를 누르지 않아도 썸네일과 15초 영상으로 무엇을 만드는지 이해한다.
- 첫 화면에서 프리셋 칩 하나로 3초 안에 제품 변화를 본다.
- 설명 없이 30초 안에 부품 하나의 색과 재질을 바꾼다.
- 공유 링크를 새 브라우저에서 열면 같은 옵션·색·재질이 복원된다.
- 터치 또는 키보드만으로도 편집과 공유를 완료한다.
- 3D가 실패해도 폼으로 편집과 공유를 계속한다.

사용성 목표는 미측정 가설이다. 구현 후 처음 보는 사용자 3명에게 같은 과제를 주고 막힌 지점을 기록한다.

## 2. MVP 범위

### 2.1 Lamp 01

편집 부품은 `base`(받침), `stem`(기둥), `arm`(암), `shade`(갓) 네 개다. 조인트·디퓨저는 고정 부품이다.

| 분류 | MVP 제안 | 동작 원칙 |
|---|---|---|
| 받침 형태 | `disc` 원형 / `square` 모서리가 둥근 사각형 | 실제 지오메트리 교체 |
| 갓 형태 | `dome` 돔 / `cone` 원뿔형 | 실제 지오메트리 교체 |
| 암 길이 | `short` / `long` | 길이에 맞는 모듈 교체, 접합 위치 갱신 |
| 재질 | `powder-coat` 분체도장 / `satin-metal` 새틴 금속 | 네 부품 각각 독립 적용 |
| 도장 색 | `chalk`, `graphite`, `clay`, `sage`, `cobalt` | 5개 고정 팔레트 |
| 금속 색 | `silver`, `champagne`, `graphite` | 3개 고정 팔레트 |
| 점등 | 켜기 / 끄기 | 디퓨저 발광, 내부 광원, 어두운 스튜디오 전환 |
| 카메라 | 자유 회전·줌, 기본 3/4·정면·측면·상단 | 이동 범위 제한, 원위치 버튼 |
| 설정 프리셋 | 기본 3개(무대 아래 칩), 사용자 저장 최대 10개 | 저장·불러오기·삭제, 이름 1–32자 |
| 공유 | 설정을 담은 URL | 계정·서버·단축 URL 없이 복원 |

형태 조합은 2 × 2 × 2 = 8개이며 모두 지원한다.

**기본값은 Atelier다.** 사각 받침·원뿔 갓·짧은 암, 받침·갓은 도장 `clay`, 기둥·암은 금속 `silver`다. 밝은 배경에서 형태가 뚜렷하고 첫 화면에서 재질 대비가 보인다. 나머지 기본 프리셋은 Chalk(원형·돔·짧은 암, 전체 도장 `chalk`)와 Graphite(원형·돔·긴 암, 전체 도장 `graphite`)다.

재질을 바꿀 때 현재 색이 새 재질에 있으면 유지한다. 없으면 `powder-coat → chalk`, `satin-metal → silver`로 바꾸고 이유를 짧게 알린다. 형태를 바꿔도 해당 부품의 마감은 유지한다. 임의 HEX 입력과 재질 수치 편집은 넣지 않는다.

### 2.2 실제 작동 / 시각적 표현 / 제외

| 구분 | 포함 내용 | 한계 |
|---|---|---|
| 실제 작동 | 회전·줌·시점 전환, 3D/DOM 부품 선택, 마감 변경, 모듈 교체, 점등 | 상태뿐 아니라 화면의 형상·재질이 바뀌어야 완료 |
| 실제 작동 | 프리셋 로컬 저장, URL 복원, 잘못된 입력 처리 | 저장 범위는 같은 브라우저·같은 사이트 |
| 시각적 표현 | 절차적으로 만든 램프, 스튜디오 조명·그림자·반사, 점등 | 실제 제품·제조 설계·광량 시뮬레이션이 아님 |
| 대체 화면 | 기본 램프 포스터와 현재 설정 텍스트 | 포스터는 현재 구성을 반영하지 않음을 표시 |
| 후속 후보 | 고객 GLB 교체 경로, AR, 분해 애니메이션, 이미지 내보내기, 샘플 가격 합계 | 의뢰나 필요가 생길 때 별도 선택 |
| 제외 | 결제·실제 가격·재고·로그인·클라우드 동기화·사용자 GLB 업로드 | 작동하지 않는 구매 버튼이나 가짜 가격을 두지 않음 |

화면 보조 정보에 “인터랙티브 컨셉 모델”로 작게 표시한다.

이 프로젝트는 절차 모델만 사용하므로 “고객 GLB로 교체 가능”이라고 주장하지 않는다.

## 3. 핵심 사용자 흐름

### A. 첫 방문 → 탐색 → 편집

1. 제품 이름·정적 포스터·편집 UI를 먼저 표시하고 3D를 지연 로드한다. 준비 전에도 폼은 사용 가능하다.
2. 기본 3/4 시점으로 램프를 보여준다. 자동 회전은 끈다.
3. 프리셋 칩이나 점등 버튼으로 즉시 변화를 본다.
4. 모델의 부품을 탭하거나 DOM 부품 목록에서 선택한다.
5. 선택한 부품의 형태 옵션, 재질, 해당 재질에서 가능한 색만 표시한다.
6. 변경 즉시 제품과 텍스트 요약을 갱신한다. 별도 적용 버튼은 없다.

### B. 저장 → 다시 열기

1. “저장”에서 이름을 입력한다. 빈 이름·32자를 넘는 이름은 같은 폼에서 설명한다.
2. 현재 설정의 스냅샷을 새 항목으로 저장한다. 같은 이름도 고유 ID로 구분한다.
3. 불러오면 네 부품과 형태 옵션을 한 번에 교체한다.
4. 10개에 도달하면 기존 항목을 지워야 함을 알린다. 삭제는 대상 이름이 보이는 확인 후 실행한다.

자동 초안은 없다. **새로고침하면 편집 중인 구성은 사라지고** 링크의 구성 또는 기본값으로 돌아간다. 보존 수단은 저장과 링크 복사다.

### C. 공유 → 수신자의 복원

1. “링크 복사”는 클릭 시점의 최신 설정을 직렬화한다.
2. 링크를 열면 해당 설정으로 시작하고 자유롭게 편집한다.
3. 프리셋 이름·카메라 좌표·선택 부품·점등 상태는 공유하지 않는다.
4. 클립보드 접근이 실패하면 선택·복사 가능한 URL 입력란을 제공한다.

### D. 실패 → 회복

3D 실패 시 포스터와 편집 UI를 유지하고 “다시 시도”를 제공한다. 설정을 초기값으로 되돌리지 않는다.

## 4. 기술 권고

| 선택지 | 판단 |
|---|---|
| React + R3F + Three.js + Vite | **권고.** DOM 편집 UI와 3D 장면을 같은 앱에서 관리한다 |
| `<model-viewer>` | GLB 감상에 적합하지만 절차 모델과 부품 조립에는 맞지 않는다 |
| Next.js + R3F | 서버 기능과 상품 카탈로그가 없어 불필요하다 |

### 승인용 기술 기본안

- React·TypeScript strict·Vite, 단일 앱. 패키지 관리자는 **npm 제안**.
- Three.js WebGL2 + R3F. Drei는 OrbitControls, Lightformer 등 필요한 기능만 사용한다. 구현 직전 stable 버전과 peer dependency를 확인해 고정한다.
- Zustand: 제품 설정과 작은 UI 상태만 보관한다. 매 프레임 카메라 좌표는 넣지 않는다.
- CSS Modules + CSS 변수. 시맨틱 HTML 중심으로 제작한다.
- 테스트: Vitest, Playwright, axe.
- DB·백엔드 없음. HTTPS 정적 호스팅(Vercel).
- WebGPU, 물리 엔진, 후처리, 전역 애니메이션 라이브러리는 넣지 않는다.

## 5. 상태 구조

데이터 흐름은 **폼/3D 선택 → 검증된 제품 설정 → 모델 표시**, 그리고 **제품 설정 → 프리셋/링크**다.

| 책임 | 보관 내용 | 제외 내용 |
|---|---|---|
| 제품 카탈로그 | 부품 ID, 허용 옵션·색·재질, 재질 레시피, 기본값 | Three.js 객체 |
| 제품 설정 v1 | 제품 ID, 받침·갓·암 옵션, 4개 부품의 finish/color ID | 카메라 행렬, 점등 상태 |
| 일시적 UI 상태 | 선택 부품, 점등 여부, 안내 메시지, 카메라 프리셋 명령 | 프리셋 데이터 |
| 뷰어 내부 | 카메라·controls 참조, 드래그, 로드 상태 | 공유 URL의 원천 |

### 저장·URL 계약

- 키는 `formlab:storage:v1`. 내용은 schema version과 프리셋 목록이다. 프리셋마다 ID·이름·생성 시각·설정 스냅샷을 갖는다.
- 시작 순서는 **유효한 FormLab URL → 기본값**이다.
- URL fragment에 버전·제품·3개 형태 옵션·4개 부품의 finish/color를 고정 키 순서로 저장한다. URLSearchParams 기반의 enum 값만 사용하고 전체는 1,024자 이하로 제한한다.
- 길이 초과·중복 키·누락 필드·알 수 없는 키/enum·지원하지 않는 버전은 전체 적용을 거부하고 기본값과 경고를 표시한다.
- URL은 링크 복사 때만 생성하고 편집 중에는 쓰지 않는다. 같은 탭에 다른 공유 링크를 붙여넣는 경우를 위해 `hashchange`는 같은 파서로 처리한다.
- 프리셋 저장 중 깨진 항목은 건너뛰고 유효한 항목만 읽는다. 다음 저장 때 깨진 항목은 사라진다.
- JSON 전체 손상·지원하지 않는 버전이면 저장 기능을 끄고 이유를 안내하며, 원본을 덮어쓰지 않는다.
- 저장 차단·용량 초과에서는 성공 메시지를 표시하지 않고 링크 복사를 안내한다.

## 6. 3D 모델

### 6.1 형상과 조립

Lamp 01은 코드로 생성한다. 단순한 큐브 묶음이 아니라 완결된 제품 실루엣을 목표로 한다.

| 부품 | 생성 방식 |
|---|---|
| 받침 `disc`, 갓 `dome`/`cone`, 기둥 | `LatheGeometry` 회전체, 모서리 bevel과 갓 두께 포함 |
| 받침 `square` | 둥근 사각 형상, bevel 포함 |
| 암 `short`/`long` | 곡선 기반 튜브, 길이별 별도 geometry |
| 조인트·디퓨저 | 고정 부품, 선택과 색 변경 대상 제외 |

- 단위는 미터, +Y 위, 원점은 받침 바닥 중심. 높이 약 0.42m, 받침 폭 약 0.18m, 암 수평 길이 0.16/0.24m의 컨셉 비율이다.
- 받침–기둥, 기둥–암, 암–갓의 socket 위치를 명시한다. 옵션별 임의 좌표 보정에 의존하지 않는다.
- 활성 옵션만 마운트한다. 숨은 옵션은 렌더링과 선택 대상에서 자연히 빠진다.

### 6.2 재질

부품마다 자기 `MeshStandardMaterial`을 선언한다. 공유 material이 없으므로 한 부품의 변경이 다른 부품에 전파되지 않는다.

초기값은 도장 metalness 0 / roughness 0.65, 새틴 금속 metalness 1 / roughness 0.32를 제안한다. 실측 물성이 아니며 시각 검증으로 조정한다.

환경 반사는 drei `Lightformer`로 코드에서 생성한다. HDR 파일이 없어 환경 자산 로딩 실패 경로가 생기지 않는다.

### 6.3 점등

- 끔: 밝은 스튜디오. 켬: 무대 배경과 환경 강도를 낮추고 디퓨저 발광과 갓 내부 광원을 켠다.
- 두 상태의 조명·노출은 각각 고정한다. 전환은 약 400ms, reduced motion에서는 즉시 바꾼다.
- 전환 중에만 프레임을 요청하고 끝나면 렌더를 멈춘다.
- 무대만 어두워지고 편집 패널은 유지한다. 시각 검토 후 조정한다.
- 켠 상태와 끈 상태 모두에서 텍스트 대비를 확인한다.

## 7. 화면과 인터랙션

### 7.1 시각 방향

따뜻한 회백색 배경 `#F0EFEB`, 글자 `#20221F`, 얇은 구획선, 작은 강조색을 제안한다. 큰 슬로건·통계 카드·유리 패널·카드 격자를 넣지 않는다. 화면의 시그니처는 **불이 켜지며 스튜디오가 어두워지는 순간**이다.

### 7.2 데스크톱

| 영역 | 배치 | 내용 |
|---|---|---|
| 상단 | 낮은 전체 폭 헤더 | FormLab, Lamp 01, 저장 목록 |
| 제품 무대 | 화면의 약 68–75% | 램프·바닥 그림자·선택 부품 표시 |
| 무대 하단 | 작은 조작 줄 | 프리셋 칩, 점등, 카메라 프리셋, 회전/줌 버튼, 원위치 |
| 편집 영역 | 오른쪽 320–360px 패널 | 부품 목록 → 형태 → 재질 → 색, 요약, 저장, 링크 복사 |

1440×900에서 램프가 무대 높이의 약 65–75%를 차지하도록 프레이밍한다. 편집 영역만 필요 시 스크롤한다.

### 7.3 모바일

- 768px 미만에서 헤더 → 제품 무대 → 프리셋·점등 → 부품 선택 → 편집 → 저장/공유 순서로 쌓는다.
- 무대는 42–48svh, 가능하면 260px 이상을 확보한다. 높이 600px 미만에서는 줄여서 스크롤할 여백을 남긴다.
- 별도 조작 모드는 없다. **Canvas 위 터치는 항상 카메라 조작**이고 페이지 스크롤은 Canvas 밖에서 한다.
- Canvas 밖에서는 pinch zoom을 막지 않는다. Canvas 위에서는 두 손가락이 3D 줌이다.
- 320px 폭에서도 가로 스크롤 없이 폼을 사용한다.

### 7.4 직접 조작 규칙

- 왼쪽 드래그 회전, wheel 줌, pan 끔. 회전과 줌에 한계를 두어 바닥 밑·제품 내부 진입을 막는다.
- 클릭 선택은 pointer down/up 이동량 6 CSS px 이하일 때만 판정한다. pointercancel·멀티터치는 선택을 취소한다.
- DOM 선택과 3D 선택은 같은 PartId를 쓴다. 선택은 외곽선과 텍스트로 보여주며 부품 색을 바꾸지 않는다.
- 빈 공간 클릭은 현재 선택을 유지한다.
- 부품 선택만으로 카메라를 움직이지 않는다. 시점 프리셋은 250–350ms 전환하고 새 입력이 오면 중단한다.
- “시점 초기화”와 “구성 초기화”를 분리한다. 구성 초기화는 확인 후 실행하고 저장 목록은 유지한다.

## 8. 접근성과 실패 처리

WCAG 2.2 AA를 설계 목표로 삼되 자동 검사 통과만으로 적합성을 주장하지 않는다.

- 네 부품과 모든 옵션을 시맨틱 HTML 폼(fieldset·radio)으로 제공한다. Canvas picking은 보조 경로다.
- swatch는 색 이름과 선택 상태를 가지며 체크 표시를 함께 둔다.
- 드래그 대안으로 회전 ±15°, 기울기 ±10°, 줌 ±10%, 원위치 버튼을 제공한다.
- 전체 흐름을 Tab/Enter/Space로 사용하고 키보드가 Canvas에 갇히지 않는다.
- 터치 영역 44×44 CSS px, 텍스트 대비 4.5:1, UI 경계·포커스 3:1을 확인한다.
- 현재 구성의 텍스트 요약을 제공하고 중요한 변경·저장·오류는 live region으로 알린다.
- 저장 dialog는 제목·초기 포커스·Escape·포커스 복귀를 갖춘다.
- reduced motion에서는 카메라·점등 전환과 damping을 끈다.

| 상태 | 처리 | 보존 |
|---|---|---|
| 3D chunk 로드 중 | 포스터, 실제 단계명만 표시 | 폼 사용 가능 |
| 3D chunk 실패 | 현재 구성 URL로 “페이지 다시 열기” 제공, 자동 reload 없음 | URL의 최신 구성 |
| WebGL2 미지원·생성 실패 | 2D 포스터 + 같은 폼·요약 | 편집·저장·공유 |
| context loss | 2D 포스터와 “다시 시도”, Canvas를 새로 생성, 자동 반복 없음 | Canvas 밖의 설정 |
| localStorage 차단·용량 초과 | 저장 실패 설명, 링크 복사 안내 | 메모리의 구성 |
| 잘못된 URL | 전체 적용 거부, 설명과 기본값 | 저장 프리셋 |

## 9. 성능 예산

다음은 **초기 목표이며 측정 결과가 아니다.** 측정은 production build에서 한다.

| 항목 | 초기 목표 |
|---|---|
| 초기 전체 전송량 | 1.5 MiB 이하 |
| shell JS / 지연 3D JS | gzip 기준 각각 180 KiB / 650 KiB 이하 |
| 활성 삼각형 / draw calls | 50k / 40 이하 |
| DPR | 상한 2, 터치 기기 상한 1.5 |
| cold load | 폼 1.5초 이내, 첫 조작 가능한 3D 5초 이내 |
| 유휴 | 조작·전환 종료 후 연속 렌더 없음 |

- 한 Canvas, demand rendering. 그림자 광원은 낮 조명과 점등 조명 두 개다.
- 측정은 production 측정 1회와 실제 휴대폰 1대의 조작 확인으로 한다. 기종·브라우저를 기록하고, 실기가 없으면 미검증으로 남긴다.
- 자동 품질 저하는 넣지 않는다. 실측에서 문제가 보이면 그림자와 DPR을 낮춘다.
